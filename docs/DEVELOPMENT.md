# 少年创想家官网 · 开发交接

> 状态提示：本文部分内容是未来方案，当前实际状态以 [当前交接](HANDOFF.md) 为准。无需按本文旧计划重建 Astro。

## 开始之前

从项目根目录读 `AGENTS.md`，产品行为以 `docs/PRD.md` 为准，数据契约看 `docs/ARCHITECTURE.md`。`site-demo.html` 是可直接打开的当前官网预览，由唯一的前端源码 `site/public/` 生成。正式版的活动读取服务位于 `site/src/worker.mjs`。

## 可连续执行的开发顺序

| 阶段 | 要做的事 | 完成判定 |
| --- | --- | --- |
| 1. 启动项目 | 在当前项目根目录初始化 Astro，保留已有文档与 `preview/`。启用 TypeScript strict 和 Node standalone，提交 lockfile。配置 `npm run dev`、`npm run check`、`npm run build` | 本地能启动，构建后可使用 `node dist/server/entry.mjs` 运行生产构建 |
| 2. 内容与页面 | 实现 `EventSource`、活动校验、状态判断、导航与页脚。先接样例，完成首页、课程、列表、详情、联系和 404 | 改一条样例记录即可从列表进入详情，首页及活动列表共用状态逻辑。活动链接稳定 |
| 3. 运营录入 | 与团队确认飞书或其他现有工具。建字段对应表和维护说明，接一个正式内容适配器，限制服务端读取权限 | 给运营一个表单或表格入口。验证新增、改期、关闭报名、补公众号回顾，无需二次部署 |
| 4. 上线确认 | 替换样例、品牌与公开联系方式，确认托管和域名，做微信内测试 | 未提供的真实地址和联系方式在公开页隐藏。官网、原文、外部报名均可用 |
| 5. 微信导入（独立） | 用现有账号的常规发文验证列表可读及权限，能用再接入增量导入。优先复用经确认的旧站同步方式 | 实际发一篇新推文，看它能进待确认列表并关联活动。再跑一遍无重复。失败时表单仍可发布 |

### 推荐目录

| 路径 | 内容 |
| --- | --- |
| `src/pages/` | 页面路由，活动详情为 `events/[slug].astro` |
| `src/components/`、`src/layouts/`、`src/styles/` | 通用界面、页面布局、全局设计变量 |
| `src/lib/events/` | 数据模型、校验、状态、排序、适配器与缓存 |
| `src/content/` | 站点配置、课程内容及本地样例 |
| `site/public/` | 当前官网页面、动效和媒体 |

运行时变量建议使用 `CONTENT_PROVIDER`。开发环境可选 `fixture`，样例明确标为示例。正式环境选 `feishu` 或采用后续确认的适配器。变量未配置时只展示已确认的静态内容及活动空态，生产环境显式选择 `fixture` 时返回配置错误。适配器在 `.env.example` 列出变量名，真实值通过运行环境注入。

## 核对用例

| 行为 | 预期 |
| --- | --- |
| 在开始前一分钟、开始时刻和结束时刻打开同一场活动 | 依次为即将开始、进行中、已结束。进入开始时间后报名立即消失 |
| 刚到报名截止、活动改期、运营标记满员或取消 | 官网展示相应提示，报名关闭。原活动页仍可访问 |
| 草稿、不存在、来源异常 | 草稿和不存在返回 404；来源异常且无快照返回 503。已缓存的回顾仍可读 |
| 公众号有预告、回顾两篇内容 | 活动前主要显示预告，发布回顾后可打开回顾。详情网址未变 |
| 新建活动或补回顾 | 在已约定的刷新时间内更新，验证普通运营账号不接触源码 |
| 手机 390、平板 768、桌面 1440 像素 | 页面无横向溢出，正文清晰，键盘焦点可见，触控目标可点按。微信内复验报名、原文和联系方式 |

当前可直接执行前两阶段。仍待提供的资料包括正式品牌素材、三类课程确认文案、团队可公开联系方式、首期活动与报名地址、选定的内容工具访问权限。以后如果要接公众号自动读取，还需确认该账号的日常发文方式与接口权限。
