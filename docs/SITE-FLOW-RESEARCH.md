# 少年创想家整站流转与动效研究

2026-11-26。工作分支 design/site-flow-research，基于正式版源码 e5092f9。本轮交付为研究与实施方案，界面开发在方案沟通之后进行。

## 网站要让家长完成的事

看懂品牌和孩子做什么，查看适合的课程，查看真实活动和作品，最后了解报名或加入社群。主页继续保留首页、课程、活动与作品、联系与合作四个导航入口。鲨鱼互动是主页中的一个体验段落。

采用主页长页加独立详情网址。首页负责让人找到内容，详情承载完整课纲、照片、日期和入口。一条活动记录可以从招募变成回顾，维持同一网址。

当前检查发现：site/public/event.html 和 event.js 有活动详情示例，主要是标题、摘要、正文和链接，尚无正式照片图集。首期真实回顾卡片按用户要求直接去视频号。课程目前点击只切简介，第三项打开企微。当前二维码可查看和下载。后续规划需兼容这些入口。

## 第一轮建议做出的完整体验

在分支实现「活动列表 → 详情 → 放大照片 → 关闭照片 → 返回列表」这条路径，用现有活动海报与作品素材搭建可审核样张。真实首期回顾继续采用已确认的视频入口；实验样张通过单独标注的入口呈现，待确认内容后再改变正式入口。

点击活动封面，封面从卡片位置扩展到详情顶部，标题随图到达阅读位置；正文轻微上移显现。返回时封面收回卡片位置，并恢复筛选状态、列表位置和键盘焦点。直接打开详情网址时正常从顶部阅读。

候选动效时长为封面320–420ms，正文180–240ms，照片打开220–300ms。这些是本项目的设计参数，须通过浏览器与手机检查后调整。

## 页面和路径

| 出发位置 | 操作与目标 | 页面呈现 | 返回与缺失内容 |
| --- | --- | --- | --- |
| 主页导航 | 点击课程/活动/联系 | 滚动到对应章节，地址保留锚点，当前导航同步更新 | 处理固定导航遮挡标题，手机原生滚动 |
| 课程目录 | 选择课程 | 稳定区域内更新简介，选中态、焦点与详情对应 | 快速连续点选只呈现最后一次选择 |
| 课程简介 | 点击查看详情 | 有内容后进入独立课程网址，课程名与版式连续 | 返回时恢复所选课程；课纲未提供时保持现有简介 |
| 线上社群 | 点击第三项课程 | 打开企微弹窗，说明了解并加入社群 | 关闭返回原课程；支持Esc、焦点返回、图片保存 |
| 活动列表 | 切换即将开展/往期 | 列表轻淡变，筛选状态可恢复 | 空列表说明暂未发布；失败可重试 |
| 活动卡片 | 点击详情 | 封面连接到详情顶部，同一活动长期保留网址 | 浏览器返回、站内返回都恢复列表状态 |
| 首期视频回顾 | 点击现有入口 | 打开用户提供的微信视频号链接 | 返回网站时恢复活动位置，手机微信实测 |
| 活动图集 | 点击照片 | 大图覆盖层，显示当前张数，键盘和轻扫翻图 | 关闭回到原照片；图片加载失败有反馈 |
| 活动详情 | 报名/提交作品/阅读原文 | 按实际数据展示对应按钮，标明外部目标 | 缺链接时隐藏入口；截止报名后更新状态 |
| 作品记录 | 翻页查看项目 | 沿用现有首页翻页手感；以后可进入项目介绍 | 不把静态截图描述成可玩的在线作品 |
| 直接访问详情 | 输入或分享网址 | 独立页面含标题、封面、日期与主入口 | 有返回活动列表入口；未知记录显示找不到内容 |

规划网址可先沿用静态文件加查询参数，例如 event.html?id=first-camp 与 course.html?id=day-camp，发布时保留 /shaonian-makers-site/ 项目路径前缀。是否升级为目录式网址在部署结构明确后决定。

## 两个参考库的取舍

### LeiBox

已浏览实时组件目录和折射波浪文档。

| 候选 | 对应内容 | 采用方式与检查 |
| --- | --- | --- |
| 字符鲨鱼与鱼群、蓝色棱纹背景 | 已上线体验段与首次开场 | 延续现有场景，控制离屏停止、减少动态和首次展示状态 |
| 折射波浪视图转场 | 两个介绍状态之间的单次切换 | 作为第二轮实验候选。文档显示React依赖，接入前核实vanilla包；先测手机性能与失败回退 |
| 拖甩照片卡片 | 主页作品记录 | 当前翻页已使用同类交互；本轮保持读图和触控习惯 |
| 弹性图片手风琴 | 桌面活动照片浏览 | 备选，需另做手机点选方案；图集阅读优先 |
| 流体提示气泡 | 导航/按钮短反馈 | 可作为细节，不能替代清楚文字与选中状态 |
| 粒子滚动、燃烧、化尘 | 大面积场景 | 暂放候选清单，先完成详情阅读与返回验收 |

## 整站流转资源与技术选择

| 资源 | 实际负责的内容 | 本项目采用建议 |
| --- | --- | --- |
| 浏览器View Transitions | 两个页面共同封面、标题的连续视觉过渡 | 首轮优先。保留正常链接，用支持的浏览器增强封面展开 |
| Swup | 页面加载、更换内容、缓存、历史、滚动恢复及扩展插件 | 备选路线。独立页面增多且需细化加载流程时，在分支做对照 |
| Barba.js | leave/enter与页面生命周期，可配GSAP编排 | 作为复杂转场研究资料，当前先记录挂载销毁方法 |
| Codrops | 完整案例、Demo与源码的教学入口 | 找预览展开为内容页的构图与时序，逐例核对源码和许可 |

推荐先使用正常多页面链接加View Transitions渐进增强。它与当前静态站的部署形式接近。浏览器不支持时仍能阅读、点击、分享和返回。跨文档共享元素要求同源且两页参与过渡，官网到微信外链只能控制站内离开之前的反馈。

Swup的官方Demo给出了fade、slide、overlay、详情modal及列表筛选例子，能学习完整路径。若以后采用Swup，需把当前立即执行的site.js拆成可重复init/destroy，主动销毁鲨鱼canvas、GSAP/ScrollTrigger、观察器和事件。不能只装一个转场库就宣称流转完成。

转场还需管理地址、当前标题、浏览器前进后退、链接预加载、正文失败状态、焦点和滚动。课程/活动每一页能独立刷新，详情缺失时可返回列表。二维码覆盖层可继续采用dialog实现。

## 内容先决定组件

课程详情先确定课程名、对象、时长、地点、学习目标、实际任务、完成成果、参与准备、价格与报名方式。未确认字段只留待补清单。

活动记录增加稳定id、关联课程id、状态、开始结束时间、封面、摘要、正文或段落、照片数组（附描述）、公众号原文、视频、报名与作品提交入口。正文和照片是详情的数据，封面是列表入口的数据。同一场活动从招募到结束后补回顾无需重新换id。

第一轮用清楚标注的样例数据做详情和往返，不编造课程承诺、正式排期或价格。实际内容由后续录入源填充。

## 实施顺序与验收

1. 在本分支先做一个活动详情样张和照片大图，验证直接打开、列表进入、返回、筛选保持。
2. 加封面共享元素过渡与短正文入场。首次开场限定首访，详情返回不重播。
3. 课程详情套用同一阅读框架，企微弹窗继续作为社群入口。
4. 再比较一次波浪/Sweep切换实验，录制浏览器效果后再选。
5. 确认内容源后接真实数据；按活动状态决定报名、作品提交与原文入口。
