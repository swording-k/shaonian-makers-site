# 前端审美与动效工作流

这份清单可以带到其他网站里用。使用本文件前，先用一句话说清访客是谁、第一眼要看懂什么、接下来要做什么。

## 按任务选择 skill

| 任务 | 先看 | 何时补充 |
| --- | --- | --- |
| 新站、重做首屏、确定视觉方向 | `design-taste-frontend` | 需要具体行业配色或字体备选时，查 `ui-ux-pro-max` |
| 在现有页面上审查、减法、调整排版 | `impeccable` | 只处理某个交互反馈时，可以直接用 `emil-design-eng` |
| 找现成的特色动效或交互组件 | `leibox` | 先写清使用场景，再看可嵌入的版本、体积和组件自带的来源说明 |
| 滚动与章节衔接 | `gsap-scrolltrigger` | 多段入场需要同一条时间轴时补 `gsap-timeline`，基础补 `gsap-core` |
| 页面闪现、掉帧或动效触发不稳定 | `animation-performance` | 问题具体发生在 GSAP 时补 `gsap-performance` |
| 需要拖拽、指针、触控驱动的新玩法 | `oil-motion` 可选 | 已有项目沿用自身栈，先做一项小实验 |
| 独立宣传视频或片头 | `kiro-motion-studio` 可选 | 只在交付物是视频时考虑 |

`leibox` 有多个安装副本时，挑一份可用且匹配任务的即可。已有 GSAP 项目的滚动工作一般直接读 `gsap-scrolltrigger`，`gsap-framer-scroll-animation` 留给确实需要对照技术路线的任务。表里记录的是使用顺序，安装情况以当前环境为准。

## 从设计到验收

1. **先看现状。** 打开真实页面，截一张桌面和一张手机首屏。记录最拥挤、最像模板、最难操作的地方，各挑一处就够。
2. **找对应参考。** 为每个问题挑一到两个真实案例。写一句具体要借鉴的东西，例如「活动封面进入详情时延续位置和比例」「固定边界让文案从同一张纸上露出」。整站案例、组件和运行时各有用途，入口见 [动效与组件台账](MOTION-LIBS.md)。
3. **把静态界面排顺。** 先定文案层级、留白、真实素材和主要行动。删除装饰标签、重复标题、等宽模板卡片、与内容无关的渐变及粒子。每屏明确一个视觉焦点，并检查关闭动画后的画面。
4. **加一条完整动效。** 明确触发、开始、结束和退出状态。优先复用当前项目的 CSS、浏览器 API 或已有动画库。开场、页面切换、悬停和滚动各有不同职责，按需要编排。
5. **在浏览器复验。** 看 390、768、1440 像素。涉及加载时再看首帧、慢网、重复打开和减少动态效果。涉及流转时检查键盘、返回、触控和真实业务入口。最后把采用的组件、来源与验证结果补到项目文档。

## 少年创想家的取舍

访客主要是家长，先看懂孩子会做什么、作品是什么、如何问课程。浅底、宋体标题和真实学员作品形成视觉基线。字符鲨鱼承担首屏的探索感，学习区只为解释表达、指挥和成果这三个步骤。首屏以短文案和一个课程按钮为主，下方保留可以咨询的输入框。大改先在分支做可点预览，视觉改动用浏览器画面确认，再决定发布。
